June 23, 2026 Learning

Day 04: Mission 1 — The Journey of a Request

Explored the fundamentals of network requests by answering: "What happens when a browser talks to a server?"

Developed a mental model of how V8 (Chrome's engine) executes JavaScript inside the Node.js runtime and routes external network payloads:

Your Code ──> JS Engine (V8) ──> Node.js Runtime (Event Loop) ──> OS ──> Hardware

Mapped out the flow of an HTTP request from a client browser down through the network stack to Port 3003, triggering our JavaScript server loops.

Remaining Questions:

  • Who stores waiting requests when the runtime is busy?
  • How does Node know which request to process next?
  • How does the browser perform DNS resolution to route requests correctly?
June 22, 2026 Integration

Day 03: Wiring Up the Express.js Backend API

Implemented the backend server architecture in server.js. Used Express to serve static files from the public/ folder and configured endpoints to handle CRUD commands:

  • GET /dreams: Fetches all pinned dreams from SQLite.
  • POST /dreams: Accepts JSON payloads, trims input, and runs database insert statements.
  • DELETE /dreams/:id: Deletes dream entries by ID once achieved.

Configured the server to listen on port 3003.

June 21, 2026 Integration

Day 02: SQLite Database Initialization & Schema

Created db.js to initialize the SQLite database connection using sqlite3.verbose(). Set up automatic table creation on runtime startup to guarantee clean workspace initialization.

Implemented database auto-creation sequence:

const dbPath = process.env.DB_PATH || path.join(__dirname, "dreams.db");
const db = new sqlite3.Database(dbPath, (err) => { ... });

db.run(`
  CREATE TABLE IF NOT EXISTS dreams (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    text TEXT NOT NULL
  )
`);
June 20, 2026 Architecture

Day 01: ED-001 — Standardizing on Node.js

Kicked off the project workspace. Documented architectural decision record ED-001 detailing stack selections for the backend builder environment.

Chosen Stack: Node.js and SQLite3.

  • Pros: Consistent JS usage across stack layers, rich package manager ecosystem, swift setup without database server hosting overhead.
  • Trade-offs: Node's single-threaded nature requires careful thread management for CPU-intensive tasks, and asynchronous loops introduce a learning curve.
